# Changelog

Each release of the AgentFlow SDK is a tag `sdk-vX.Y.Z` on both
`reflexify/agentflow-sdk` and `reflexify/agentflow-app-template`. Its section says which
`configVersion` and package `formatVersion` it writes, the oldest AgentFlow platform version
it needs, and the result of running the skills on a fresh copy of the template.
Its `Skills dry run:` line names every skill the dry run covered, and the release check refuses a line that leaves out a skill the plugin ships.

## Unreleased

## sdk-v0.12.0

configVersion: 1
formatVersion: 1
minPlatformVersion: 2026.10
Skills dry run: skipped for this release at the owner's request (a quick release); the skills agentflow-app-authoring, agentflow-app-release, agentflow-ui-module and agentflow-from-draft were not run on a fresh copy of the template, so the changes below, like those of sdk-v0.11.0, are not yet covered by a dry run. The next release's dry run covers them.

A kit hover is a pointer's now: every `:hover` rule in `kit.css` and in the elements' own styles sits inside `@media (hover: hover)`, as AgentFlow's Tailwind `hover:` variant does, so a tap on a touch screen no longer leaves a button, chip, toggle, tab, row, card or link hovered until the next tap elsewhere. Focus and press rules are not inside it. Nothing changes for a mouse, and a stylesheet of your own that copies a kit hover for your markup should sit in the same query. Two selectors lost a `:hover` that did nothing: a selected card and a selected or current list row, which already won over the hover ground by coming later at the same weight.

A kit tag the page has not defined yet gets the layout it has once defined, so a tag a server drew does not jump when the kit loads: `KIT_CSS` and `kit.css` give each of the twenty-seven tags a `display`, which is the one its element sets on `:host` for most, a block for `af-menu`, `af-person-picker`, `af-popover` and `af-rich-editor` (they set none and draw a block-level box in an inline host), and `contents` for `af-dialog`, `af-confirm`, `af-toast` and `af-bulk-bar` (they draw no box). `af-select`, `af-combobox`, `af-number-input`, `af-date`, `af-tree-picker`, `af-person-picker`, `af-tabs` and `af-menu` also get a least height of 36 px, `af-select size="sm"` and `af-tabs variant="segmented"` 32 px, and `af-copy-button` 24 px by 24 px, the heights they have once defined. Nothing is hidden, so a page the kit never loads shows what it put inside the tags, and the selectors carry no weight, so a rule of your own for a tag wins. `af-scroll-area` and `af-splitter` keep the display they had, now only until defined, where it was written for the defined tag too.

`af-dialog`, `af-confirm`, `af-toast` and `af-bulk-bar` are `display: contents` once defined, as `kit.css` has them until then: each was an inline host that drew nothing of its own, which in a flex or grid parent became an item and took a gap, so a tag a page put in a row opened a gap when the kit loaded. The wrapper inside the toast's and the bar's shadow root is `display: contents` too. What each shows is in the top layer, so nothing else changes.

`af-popover`'s content no longer runs past the edge of a screen under 320 px wide: its least width is `min(18rem, calc(100vw - 32px))`, where the fixed `18rem` beat the greatest width `min(28rem, calc(100vw - 32px))` there. On a wider screen it is the 288 px it was.

`af-tooltip` draws an arrow, as AgentFlow's tooltip does: a 10 px square turned 45 degrees and rounded 2 px, in the bubble's colour, 5 px of it outside the bubble. The kit's contract grows by one part, `arrow`, present while the tooltip shows; `::part(arrow)` takes `--arrow-size` and `--arrow-background`, and `display: none` on it removes the arrow. The bubble now sits 10 px from its anchor, where it sat 8 px, so the arrow's tip is 5 px from it. Nothing else about the tooltip changed: its text, its delay, its keys and its part `anchor` are as they were.

`af-combobox` and `af-person-picker` keep the first key typed after a quick click on their field's label while their list is open. The list judged that click a press outside a frame later, after the key, and closing then wiped the key; a press that takes focus from the input and gives it back, as the label's click does, no longer closes the list. A press elsewhere still closes it, even one that leaves focus in the input.

The kit's controls follow a right-to-left page: `af-tabs`, `af-menu`, `af-select`, `af-combobox`, `af-person-picker`, `af-date`, `af-splitter`, `af-number-input` and `af-tree-picker` take the direction of the closest `dir` attribute above them (or their computed `direction`) when they are drawn, where every one ran left to right before and `af-number-input` said so outright. Under `dir="rtl"` ArrowLeft moves to the next tab and moves a splitter's handle left, which grows the start pane; `size` is still the start pane's share. Nothing changes on a left-to-right page. A pointer drag of the splitter is not yet mirrored.

A press on an `af-menu`'s trigger while another `af-menu` is open now closes the open one and opens the pressed one, as AgentFlow's dropdown menus do. Before, both ended closed: the menu opened second was taken as nested in the first, so the first one's close dismissed it too.

An `af-tooltip` showing inside an `af-dialog` takes the first Escape, as one inside an `af-popover` already did: an Escape pressed on the tooltip's anchor closes the tooltip alone and emits no `close`, and the next Escape closes the dialog. Before, one Escape closed both.

A focused kit control's border and ring are now opaque where a host sets no `--af-ring`: `AF_DEFAULT_PALETTE['--af-ring']` and the kit's fallbacks are the primary at full strength (`oklch(0.55 0.17 254)` light, `oklch(0.74 0.13 248)` dark) where they were that colour at 40% and 50% alpha, about 1.6:1 on white against the 3:1 a focus indicator needs. AgentFlow's own `--ring` is opaque in every theme, so a kit control inside it follows. A host that sets `--af-ring` itself is unchanged; a module's own controls still draw a solid `--af-primary` outline.

`af-file-upload` writes a size under 1 KiB as `512 B`, the unit AgentFlow's formatter writes, where it wrote `512 byte` (`512 B` in Vietnamese too); kilobytes and megabytes read as they did. A drop with more files than the field takes now gets the count notice (`At most 3 files.`, `One file only.`) even when one of its files is of the wrong type: the type notice came first before, because only the files of an accepted type were counted. A file that appears twice in one drop (the same name, size, type and modified time) was added once with no word; `notice` now says so, in a new optional `KitStrings` key, `fileDuplicate` (`{name} appears more than once; it was added once.`, with Vietnamese text), and the file is still added once. The element also empties its hidden file input after each pick. A disabled element, or one inside a disabled `fieldset`, already cancelled a drag over its drop zone and a drop on it; the README says so now.

`af-bulk-bar` reads a `total` that is empty or 0 as no total: the attribute `total=""` arrives as a 0 and showed `3 of 0 selected`; it shows `3 selected` now. An action wrapped in an `af-popover` and chosen from the bar's menu is now shown, from the click until the overlay it opened closes, where its popover anchored on a hidden box and opened at the top left of the window. That holds when the choice is sent to the bar's `more` part from code. Chosen from the open menu with a pointer, the popover still closes at once, since the menu returns focus to its button and the popover reads that as a press outside; that is a known open issue. The overlay must be raised by the microtask after the click (the bar waits one `tick()`), and a plain button is clicked while hidden as before. And in a window too narrow for the summary, the menu's button and the clear button, the summary is cut short with an ellipsis, where the buttons overlapped each other and the clear button ran out of the bar. Nothing changes while an action fits beside the menu.

`af-tree-picker`: a Space picks the node with focus only when no typeahead is running (Enter always picks): typing "Ha N" no longer picks a node at the space, and a Space more than 350 ms after the last typed key picks as before. A chosen node that is disabled is no longer drawn on the accent ground, semibold: the look of a chosen node is for one that can be picked, as in AgentFlow's `TreeSelect`. And a node under a cycle (`c` with parent `a`, where `a` and `b` are each other's parents) is drawn under the cycle, which is cut at the member the walk up from `c` meets first (`a`), where `c` was a second root beside it.

`af-signature-pad`: `clear()` on a pad with nothing on it (no strokes, no `value` image) or on a `readonly` pad now does nothing and raises no `change`; it raised `change` with `null` both times, and on a read-only pad the image stayed. A stroke's export that never finishes (Zag sets no handler for the image failing, so a page whose policy refuses a `data:` image waited for ever and went on submitting the stroke before) is given up after five seconds: the pad logs a `console.warn`, raises no `change`, and submits no image. An empty `readonly` pad is a bare box now, where it was a `role="img"` named by `label` with nothing in it; with a `value` it is still the named image.

`directory.units` leaves `archived` out of a node when the server did not say, where it wrote `archived: false`: an installed app is told a unit's `archived` only while its package lists the `org_unit` entity's field, and the row of an app whose package leaves it out was claimed to be live. A node the server called live or archived carries `archived: true` or `false` as before; `af-tree-picker` and every other reader of a `TreeNode` treat an absent `archived` as not archived, so nothing is drawn differently. A page that compared `node.archived === false` should read `!node.archived`.

An `af-checkbox` whose `indeterminate` property is set now draws as AgentFlow's checkbox does in that state: the box is filled with the primary colour, its edge the primary and its dash in the colour that reads on it, where it was an empty box with a dash in the text colour. It follows `:indeterminate` as well as `:checked`, so a box that is both is filled too, and in forced colours it takes the `Highlight` fill with a `HighlightText` dash. A filled box that is also invalid keeps its primary edge, as it did.

A hard break inside a task-list item of `af-rich-editor` stays in that item when the Markdown is loaded again. The editor writes it as it always has (`- [ ] a\` and `b` on the next line, as CommonMark reads it), but it read the line after the break back as a paragraph of its own below the list, and the break as a literal backslash, so each save moved the text out of the item. Nothing it stores changes.

**Breaking: `work.document` moved to the entity's `document` member; a package in the old form is refused.** The document contract is an entity's own setting, beside `work` and not inside it: write `"document": { "extract_fields": [...], "context_fields": [...] }` on the entity, with the same rules. `pnpm build` refuses `work.document`, whatever its value (`entities/<key>.json#/work/document: DOCUMENT_CONTRACT_MOVED: The document contract is the entity's own "document" member since platform 2027.06, not part of "work".`), and so do AgentFlow's lint (`document_contract_moved`) and its package verification at upload (`DOCUMENT_CONTRACT_MOVED`); move the block and build again. `DOCUMENT_PLATFORM` is now `2027.06`: the build raises `minPlatformVersion` to it for an entity that declares `document`, and an older AgentFlow refuses the member. An entity a source fills declares no `document`, as it declares no `work`. A draft converted with `agentflow-app init --from` carries the member as it is. `DOCUMENT_CONTRACT_MOVED` and `DOCUMENT_CONTRACT_MOVED_TEXT` are exported beside `DOCUMENT_PLATFORM`. A breaking change under 0.x is a minor bump, so the next release is `sdk-v0.12.0`.

A group in a people field now lets the group's services read, as it lets its people. A `read` or `list` record scope of kind `field` or `parent_field` on a grant to a group reaches the active service principals in that group as well: a service matches the field through the groups it is in and the units it is placed in exactly, never through its own id. So an unattended run, or a service calling with an `afk_` key, reads the records whose field names a group it is in, which is how an app keeps an agent to what the people it acts for may read. Writes, a `work` scope, an `everyone` grant and a grant to the service principal itself still reach people only, and a record scope on the last is still refused. Nothing in a package changes. The install plan still warns `run_account_access_missing` for an automation account in the group that reads only through a record scope on that group's grant, when the same plan writes the grant; the warning can be ignored for it (an account not yet in the group is warned for real), and a grant already stored draws none. The `agentflow-app-authoring` skill's `access.md` ("Record scopes" and the bullets above it) and `workflows.md` say so. The platform side needs an AgentFlow that serves it; an older one reads nothing more for the service.

`pnpm build` checks a document template's layout against the platform's own schema of it, which `@reflexify/agentflow-app-builder` now ships as `schemas/block-tree.schema.json`. A member no block has (`.../content/0/mark: a member the block tree has no place for here; the members each block takes are in schemas/block-tree.schema.json of @reflexify/agentflow-app-builder`), a value outside a member's set (`.../align: must be one of left, center, right, justify`), a wrong type, a missing required member, a heading level past 3, a column group of fewer than 2 or more than 4 columns and a repeated row without `loop_as` are refused at build with their place, where AgentFlow refused them only at install or dropped a misspelt member silently. A `null` on a member that is not required still reads as absent. A template that built before and is refused now is one AgentFlow refuses at install (a one-column `column_group`, for one) or misreads (a misspelt member it drops), with one exception: the old spelling `paragraph_spacing` in `settings`, which AgentFlow still reads as `space_after`, is refused; write `space_after`.

The authoring skill has a reference for a document template's whole layout, `document-templates.md`: every block and inline item, a drawn table with a row repeated per list item (line items with a row number, masked amounts and a total row, as a complete example) beside the data table, columns, lists, date and number masks, page setup and sections, the running header and footer with page numbers, Markdown text, expressions and show-when conditions, what the build checks and what only the install refuses, a document that fails to render without failing its step, and what differs between the PDF and the Word file. `steps.md`, `pitfalls.md` and `SKILL.md` point to it.

## sdk-v0.11.0

configVersion: 1
formatVersion: 1
minPlatformVersion: 2026.10
Skills dry run: skipped for this release at the owner's request (a quick release); the skills agentflow-app-authoring, agentflow-app-release, agentflow-ui-module and agentflow-from-draft were not run on a fresh copy of the template, so the changes below are not yet covered by a dry run. The next release's dry run covers them.

`sandbox.json`'s `install.decisions.parameters.<package id>.<key>` resolves an `@group:<key>`, `@unit:<key>`, `@principal:<key>`, `@person:<handle>`, `@connection:<key>`, `@sla_policy:<key>` or `@escalation_policy:<key>` as `install.parameters` does, so a dependency's parameters can name the sandbox's groups, principals and connections. `sandbox check` and AgentFlow refuse one that names nothing in the file (`SANDBOX_SPEC_INVALID` at `install.decisions.parameters.<package id>.<key>`); a boolean, a number, a string with no `@` and an `@` string of a kind the file does not know are passed as given.

A sandbox can install and test a package that requires `rfx/erp-core`. `sandbox.json` takes a connection of `kind: "sandbox_erp"`, an ERP connection that calls no ERP and takes neither a secret nor settings (`connections[i].secret_env: a sandbox_erp connection takes no secret`, `connections[i].settings: a sandbox_erp connection takes no settings`), and a new member, `dependencies`, a list of sealed `.afpkg` files: `deploy --sandbox` (and `--upgrade`) uploads each with the sandbox's deploy key before the folder's package, so the install finds erp-core among the sandbox's uploads; the CLI keeps the member to itself and does not send it to AgentFlow. `sandbox check` and `deploy --sandbox` refuse a dependency file that cannot be read or holds no manifest, and compare `install.decisions.parameters["<its id>"]` with that dependency's parameters as they compare `install.parameters` with the package's. The refusal of a package that requires `rfx/erp-core` (`requires.packages: the package requires rfx/erp-core, which cannot be installed in a sandbox`) is gone. An `erp` `connection_ref` is refused only when the file declares no `sandbox_erp` connection, and an `erp` parameter answered with an email connection, or an email one answered with `sandbox_erp`, is refused. The warning about a required package now reads `requires.packages: <id> is not among sandbox.json's dependencies, so the install looks for it in the deployment's app catalog, …`. Two commands drive the connection: `agentflow-app sandbox records-in --connection <key> --stream <stream> --file <records.json>` records canonical ERP records on it, which erp-core's sources and the app's triggers then read as an ERP read's; a bare record is keyed by its `company_erp_id` (or `""`) and `erp_id` and stamped with its `source_changed_at` unless the file gives a `key` and `stamp`, and a file is sent in requests of at most 500 records and under 2 MiB, one output line each (`records 1-500: recorded 499, 1 already there`). `agentflow-app sandbox records-out --connection <key>` lists the draft bills apps wrote to it (`--json`: `{"writes": [...]}`). They need an AgentFlow build with the `sandbox_erp` connector; an older one refuses the kind (`` `sandbox_erp` is not supported; only `resend` and `loopback` are ``) and answers the two commands `404`. The release skill's `sandbox-json.md` ("Connections", "Dependencies" and "What a sandbox cannot hold") and `sandbox-testing.md` ("Testing an app on `rfx/erp-core`") say how.

Adding a profile link to an entity that already holds records is now refused by the plan, before any step runs: `APP_PROFILE_LINK_NEEDS_KEY_FIRST` at `/inverse_key` on the field, with the same advice as before (ship the `natural_key` entry in one release and the `inverse_key` in the next), where activation used to fail the field. An entity with no records still takes both in one release. A creator default on a reference to a profile entity now pins the link it fills from: clearing the link's inverse, adding a second link or deleting the link is refused while a default fills from it, and a release that drops the link drops the defaults in the same release (the install takes them off first, in either manifest order). `agentflow-app lint` no longer reports `ceiling_uncovered` for a profile name read through a user field (`subject.record.approver.rfx_hrm__employee.title`). The built-in Users field `is_active` reads "Account active".

`<agentflow-start-form>`'s folder field offers Try again (`form.folder_retry`, part `field-retry`) when the folder picker's code fails to load, so the person need not reload the page; the failure's own sentence is unchanged.

The authoring skills now say what the AP-match team asked: an installed erp-core loads open documents and all master data on its first poll (it no longer says there is no first load); an Integration `get` that finds nothing succeeds with `null`, and a failure fails the step; a Human step can be assigned to a person a record field names, by id only; `event.previous` holds only the changed fields, a filter may compare two variables, and a rollup fires its parent's trigger; rules never judge a delete; a workflow reads a record's rollups as fields; a `reference_list` keeps its order.

`pnpm build` refuses a `code/` file larger than a Code step's source may be, 256 KiB counted in UTF-8 bytes, naming the file and its size. The platform already refused such a step, but only when the workflow was published at install. The limit is per step, so a file two steps use counts for each. `CODE_SOURCE_MAX_BYTES` is exported for an app's own size test.

`createMany(id, name, entity, itemsPath, body, { itemAlias?, indexAlias?, destinationUnit? })` writes an Entity Record step that creates one record per element of a list: the body reads the element as `item.<field>` (or under `itemAlias`), the step's output is the created ids in list order, and it writes all of them or none, at most 5,000 (`ENTITY_RECORD_CREATE_MANY_TOO_MANY`). The build checks its list path as it checks the step's other reads. It works in an all-or-nothing workflow and in a For each body.

`updateEach(id, name, entity, itemsPath, idPath, body, { itemAlias?, indexAlias?, expect? })` writes an Entity Record step that updates each record a list names with that element's own values: `idPath` (`"item.id"`), the body and `expect` read the element as `item.<field>` (or under `itemAlias`), and the step's output is `updatedCount` and the updated ids in list order. It writes all of them or none, at most 5,000 (`ENTITY_RECORD_UPDATE_MANY_TOO_MANY`): two elements naming one record (`ENTITY_RECORD_UPDATE_EACH_DUPLICATE`), a record not found (`NOT_FOUND`) or an `expect` that no longer holds (`ENTITY_RECORD_UPDATE_EACH_EXPECTATION_UNMET`) fails the step and names the element. It takes no filters, writes no File field and does no list append or remove, and a test run does not check that the records exist. Any other option is refused at build, and the build checks its list and record id paths as it checks the step's other reads. It works in an all-or-nothing workflow. It names no platform month: an older AgentFlow cannot parse the step, installs the package all the same, and fails the step when it runs, writing nothing, so upgrade the platform first.

`formatNumber` and the figures rules write a number below 1 without `decimal_places` with three significant digits: `0.000123` (`0,000123` in Vietnamese) where they wrote `0`, and `0.0457` where they wrote `0.046`. Zero, a value of 1 or more, a value with `decimal_places` and a currency are unchanged, and a percent reads `0.000123%`.

`pnpm build` refuses a `minPlatformVersion` below the SDK release's floor, `2026.10` (`package-manifest.json#/minPlatformVersion: 2026.09 is below this SDK's floor, 2026.10: …`), where it wrote the lower month into the package. `2026.10` and later months build as before, a month a feature raises is still raised, and a value that is no month is left for verification. `PLATFORM_FLOOR` is exported beside the builder, and the release check refuses a release section whose `minPlatformVersion:` line is not that month.

`email-events.md` types `email.received`'s `plus_tags` as `plus_tag_list`, a list of `{ address, tag }`, where it read `object`. The value is unchanged; AgentFlow's designer offers it as a list whose items carry `address` and `tag`, and still never as a filter field.

The document contract's `context_fields` (the entity's `document` member, see the Breaking entry above) may name `unit` on an entity that says `requires_unit_classification: true`: package verification refused it (`PACKAGE_BODY_INVALID`) and `pnpm build` refused it (`entities/<key>.json#/work/document/context_fields/<n>: unit is not a field of <key>`, from the form it then had), though AgentFlow's own save accepts it. On an entity that does not classify its records it is still refused, and `extract_fields` never takes `unit`. `unit` is a reference, which the model is never shown, so naming it is allowed and reads nothing; `work.md` says so.

`pnpm build` refuses two workflow mistakes publish refuses. First, a path that names a step no path of edges leads from, so the step has not run when the path is read (`workflow one#/graph/nodes/1/parameters/assignments/0/value: early reads nodes.later.output.x, but no edge path leads from later to early, …`), in the positions where it already refused a missing step: an Entity Record step's record id, body, filters and `q`, a Set Variable step's assignments, a Decision's conditions, a For each step's list and a per-item Email step's list. A step upstream by any path builds, a loop's back edge included, so a Join may read both arms while an arm may not read its sibling; in a loop's body, `parent.nodes.<id>` must be upstream of the For each step. These refusals, and the missing-step ones, now name the workflow by its key and their place as a pointer from its root, a loop's body included (`workflow <key>#/graph/nodes/…`), as the workflow's other refusals do, instead of `<name>: …`. Second, a search's `fields` key that is not a field of the package's own entity (`workflow one#/graph/nodes/1/parameters/fields/1: nope is not a field of entity:contact, and a search returns only fields its entity has`): a declared field, one the entity's work adds, `name`, `created_at`, `updated_at`, `created_by`, `owner` and, on an entity classified by unit, `unit` build, and a search on a dependency's entity, or one whose `fields` holds a key that is no string, is left to the install. A `bind`, `flt` or `sort` key and a template's names are still not checked; the authoring skill's "What `build` does not check" says so.

`pnpm build` refuses an entity field's `format_options` value or constraint that AgentFlow refuses at install, judged by the type of the field's values (a formula's result type, an `auto_number`'s `number` without a code template and `text` with one): an option the type or format does not take (`currency_code` without `format: currency`, `separators` or `decimal_places` on a `rating` or `duration`, `time_style` off a datetime, `mentions` off a text field, `display` and `done_field` off a list), a value outside its set (`entities/x.json#/fields/0/format_options/rating_max: a whole number from 1 to 10`; a `currency_code` of three capital letters, `max_files` 1 to 500, at most five `bar_bands` of `{ at, color }` with `bar: true`), a constraint the type does not take (`min_items` on a list, any on a date), a list's `max_items` outside 1 to 200, `enforce_format` without `format: email` or `url`, a minimum above its maximum and a `pattern` over 500 characters. What AgentFlow drops before it judges is dropped here too: a null `max_files`, `mentions: false`, `bar: false` with its bands, and a null constraint member such as `min_length: null`. `constraints: null` and `rollup: null`, which `pnpm build` refused, now build, as AgentFlow reads them as absent. Whether a `pattern` is a regular expression AgentFlow takes, and a checklist's columns, are still left to the install; `entities.md` lists the values.

`agentflow-app lint` reports `profile_link_invalid`: an `inverse_key` on a reference to Users that is not a single, unsecured reference whose entity has a `natural_key` over that field alone, under a handle that is a local key and that no user field and no other field of the package has, and any `inverse_key` on a reference to groups or units. AgentFlow installs such an inverse under the package's prefix and packs it back as the local handle. Lint runs on the platform, so the code needs an AgentFlow build that has it. The release skill's `lint-problems.md` lists it.

A workflow path reads a person's profile through any user value: `workflow.requester.<inverse>.<field>` and `<user field>.<inverse>.<field>`, where `<inverse>` is the installed name of the inverse a reference to Users declares (`rfx_hrm__employee`). It reads as the run's principal, a person with no profile reads as empty, and publish checks the name and one field below it. `./workflow` gains `installedKey(packageId, key)`, which writes that name (`installedKey("rfx/hrm", "employee")` is `"rfx_hrm__employee"`) and refuses a package id with no `/`, and `getByKey(id, name, entity, matchKey, body)`, an `entity_record` `get` through a `natural_key` set that answers `nodes.<id>.output.found` and `.record` and writes nothing. `agentflow-app lint` no longer reports `installed_key_literal` for a word that is the package's own prefix and the `inverse_key` of one of its own references to Users; any other own-prefixed word is reported as before. The authoring skill documents the profile pattern (`entities.md`, "A person's profile"; `workflows.md`, "A person's profile in a path"). It needs an AgentFlow build that reads profile paths; an older one refuses the workflow at publish.

A module can open AgentFlow's file preview on a list of files. `host.files.preview(files, { start })` (app contract 6, a new optional member of `AppHost`; `APP_CONTRACT_VERSION` is 6) takes a file id, an `{ file, filename? }` or a list of either, at most 200, and the index to open on. The SDK gains the conventions the kit's pickers follow, as plain functions with no DOM, exported from `@reflexify/agentflow-sdk`. `fold(text)` is lower case with accents off (`đ` included), and `matches(text, query)` is whether the text holds the query, ignoring case, accents and the space around the query; an empty query matches anything. `parseDateInput(text)` reads a typed `dd/mm/yyyy` or `yyyy-mm-dd` as `yyyy-mm-dd`, or `null`; `validIsoDate(text)` and `isoDate(year, month, day)` answer `null` for a day that does not exist (`2026-02-30`); `todayIsoDate()` is the viewer's today; `formatDate(iso, locale)` writes `05/11/2026` for Vietnamese and `5 Nov 2026` for anything else, reading the day as UTC so it never moves. `relativeTime(iso, locale)` and `absoluteTime(iso, locale)` are AgentFlow's own, copied unchanged from its frontend so that it can move onto them later: `relativeTime` reads a week or more as a date, and with `en` it gives the US order (`Oct 27`), where `en-GB` gives `27 Oct`. `af-date` and `af-person-picker` now call the same functions, so a module that formats or searches through them agrees with the elements. The types `PickerQuery` (`{ q, cursor, signal }`), `PickerPage<T>` (`{ items, next }`) and `PickerSource<T>` (a function from a query to a page, with an optional `resolve(ids, signal)` that names the options for ids a picker holds and has not listed) are exported from the SDK and re-exported from the kit. `af-combobox` takes one, and the directory sources of a later release produce them.

`af-date`, `af-person-picker` and the three inputs below are now form-associated custom elements: inside a `<form>`, in a page or in a shadow root, they take part as an `<input>` does. Each gains six properties, all of them attributes too: `name`, `required`, `readonly`, `description`, `error` and `invalid`. `name` puts the value in the form's `FormData`: `af-date` as one entry, `af-number-input` as one entry written as `String(value)` writes it, and `af-person-picker`, `af-select` and `af-combobox` as one entry per value, so `multiple` gives several under one name; an empty value submits nothing. `required` with no value is `valueMissing`, and a date or a number before `min` or after `max` is `rangeUnderflow` or `rangeOverflow`, each with a message in the element's language. The elements have `form`, `validity`, `validationMessage`, `willValidate`, `checkValidity()` and `reportValidity()`, and `focus()` reaches the inner input, because their shadow roots now delegate focus. Values are controlled, so `form.reset()` cannot clear an element: it emits `change` with the element's default value (its `value` attribute, otherwise empty) and nothing when it already holds that, and the page sets the value back as for any `change`. An ancestor `<fieldset disabled>` disables the control, and its own `disabled` property stays as set. Setting `name`, `disabled` or `readonly` as a property writes the attribute back, because the browser reads the attribute. `description`, `error`, `invalid`, `required` and `readonly` are for accessibility only: they become the inner input's `aria-describedby`, `aria-invalid`, `aria-required` and `readonly`, and the element draws none of them. Drawing the visible label, help text and error is `af-field`'s job.

The UI kit grows from ten elements to sixteen. `<af-number-input>` takes `value` (a number or `null`), `min`, `max`, `step`, `precision`, `format` (`plain`, `currency` or `percent`), `currency` (an ISO 4217 code, `VND` by default), `steppers`, `placeholder`, `label`, `disabled` and the six form properties. It shows the value as the browser's `Intl.NumberFormat` writes it for the element's language (`1.234,5` in Vietnamese, `1,234.5` in English, `1.500.000 ₫`, `15%`). `step` is 1, or 0.01 (one point) with `format="percent"`, and `precision` is 0 when `step` is a whole number in the units shown and 2 otherwise. While the input has focus it keeps what the person types, in the language's separators; a commit (blur, Enter, an arrow key, PageUp or PageDown, or a stepper) parses it and sends `change` with `{ value: number | null }`, and the element shows the value again, formatted, once the page sets it back. The arrow keys step by `step`, PageUp and PageDown by ten steps, and neither goes past `min` or `max`; a typed number outside them is sent, and the form calls it `rangeUnderflow` or `rangeOverflow`. The mouse wheel never changes the value. Its parts are `control`, `input`, `increment` and `decrement`. A blank `value` attribute on `af-number-input` (`value=""`) is no value, shown empty and read as `null` on a form's reset.

`<af-select>` chooses from a short list. It takes `options` (`SelectOption[]`, each `{ value, label, disabled?, reason? }`), `value` (an option's value, an array of them with `multiple`, or `null`), `multiple`, `placeholder`, `label`, `disabled` and the six form properties, and it sends `change` with `{ value }` in the shape of `value`. The trigger shows the chosen option's label, or with `multiple` every chosen label in the order of `value`; a value `options` does not hold shows the `placeholder`, never the raw value, and is still submitted. A disabled option is never chosen, shows its `reason` in a tooltip and carries it as its `aria-description`. Typing a letter on the closed trigger opens the list and highlights the first option it starts, and Enter or a click picks. `readonly` keeps the list closed and sets `aria-readonly`. Its parts are `trigger`, `value`, `indicator`, `content`, `option` and `empty` (an empty `options` says "No options"). Use it for at most about fifteen options, and `af-combobox` past that. In `af-select` and `af-combobox` a `value` of `''` is no value, as `null` is, so every option needs a non-empty value.

`<af-combobox>` is typed into to find a value. It takes what `af-select` takes, plus `loading` and `source`, and its `options` are `ComboboxOption[]`, a `SelectOption` with an optional `description` drawn muted beneath its label. Without a `source` it filters `options` itself by label and description, ignoring case and Vietnamese accents; with `multiple` the chosen values are removable chips beside the input, and in single mode `clear` sends `{ value: null }`. With a `source` (a `PickerSource<ComboboxOption>`, which wins over `options`) it asks the source: `source({ q, cursor: null, signal })` when the list opens from the keyboard and 250 ms after typing stops, each call aborting the previous one's `signal` so that an answer arriving late is dropped. A `loading` row shows while a call runs and a `load-more` row while the last page's `next` is set. For a value no loaded page has named it calls `source.resolve(ids, signal)` once, keeps every item it is given so that a chosen value keeps its name, and shows a value nothing could name as "Unknown value". Pass one stable function, a module constant or one memoised for the page's lifetime: a new function restarts the list and asks afresh. The list does not open on a click; keys and typing open it, as `af-person-picker`'s does. A source that rejects is not drawn yet, and reads as no matches. It sends `change`, and `search` with `{ query }` as the person types. Its parts are `control`, `chip`, `remove`, `input`, `clear`, `content`, `option`, `empty`, `loading` and `load-more`. With `multiple`, `focus()`, a click on its `af-field`'s label and a press on a chip's text put focus in the input, never on a chip's remove button, and `af-person-picker` does the same.

`af-date` has a range mode. `range` (a Boolean attribute) with `start` and `end` (ISO strings, either of which may be `null` for an open end) picks a span. The element then draws two inputs, `part="input start"` and `part="input end"`, with an en dash between them (`separator`), named "Start date" and "End date" after `label` when it is set, and `change` carries `{ start, end }` where it carries `{ value }` without `range`. `value` keeps its type and is ignored in range mode, so no existing property changed meaning. Each input accepts typed text as the single input does; an end earlier than the start, or a changed end outside `min` and `max`, is refused and the input shows its end again. In the calendar, picking a start and then an end sends `change` once, with both; Clear empties both ends. The form value is `start/end`, with an empty side for an open end (`2026-11-01/`), and a reset sends `change` with the `start` and `end` attributes' values. The typings tie the `onchange` detail to `range` and add `DateRangeChangeDetail`.

`<af-field>`, `<af-fieldset>` and `<af-form>` draw a form as AgentFlow's forms look and submit it. Unlike every other kit element they have no shadow root: they enhance the children the page writes, React's included, and never move one. Each inserts nodes of its own, marked `data-af-owned`, and puts those first and last when the page adds, swaps or removes a child, so a conditional control works as it would in a `<div>`. `af-field` takes `label`, `description`, `error`, `invalid`, `required`, `readonly`, `locked-reason` (the property is `lockedReason`) and `name`. Its control is its first child that is neither its own nor in a slot, and a child with `slot="aside"` sits in the label row. A native control gets an id, a `<label for>`, `aria-describedby`, `aria-invalid`, `required` and `readOnly`, and takes back only what the field set. A `role="radiogroup"` or `role="group"` container is named with `aria-labelledby`. A kit control gets what the field has of `label`, `description`, `error`, `invalid`, `required` and `readonly` as its own properties, keeps its own where the field has none, and gives back only what the field wrote; `invalid` is also set while there is an `error`. `locked-reason` makes the control read-only and adds a lock button whose tooltip shows the reason, which is also in the control's description, hidden. On a native `<select>` or a `role="radiogroup"`, read-only is only `aria-readonly="true"`, which cannot stop a person changing it, so the page keeps the value. `af-fieldset` takes `heading`, `description` and `columns` (1 to 3). Around a native `<fieldset>` that the page writes as its child, it inserts the legend and the description and draws that fieldset as the section card, so a disabled fieldset still disables every control in it, the kit's included; without one, it is the card itself. A child's place on the grid comes from `data-span` and `data-col`. `af-form` enhances the native `<form>` the page writes as its first child, so the browser's own validation, `FormData` and a disabled `<fieldset>` keep working. Its submit becomes `af-submit` with `{ formData, submitter }`, and not `submit`, because the form's own `submit` already bubbles through the element. It is sent once until the page has had its turn, so a double press emits once, and not at all while the page has `busy` set (the submit buttons carry `aria-disabled`). `errors` takes the server's `{ path, message }` list (`FormError`): a JSON Pointer path (`/address/city`) names the `af-field` whose `name` is `address.city`, the message becomes that field's `error`, and a message that names no field goes into a summary, a danger banner that is the form's first child, with a link to each field that has an error. Setting `errors` with other content moves focus to the summary, or to the first field with an error; the same list again, in a new array as React passes on each render, places the errors and leaves focus alone. While `dirty` is set the element holds a `beforeunload` listener on `window`, so leaving the page asks first. That is the kit's one listener there, and it goes when `dirty` clears or the element leaves the page. `af-form` holds no values, validates nothing and saves nothing: those stay the page's. The classes the three draw are in the README's "Fields and forms".

`KitStrings` gains fifteen keys, all optional as every key added after the first release is, each with English and Vietnamese text: `valueMissing`, `rangeUnderflow`, `rangeOverflow`, `increase`, `decrease`, `numberUnderflow`, `numberOverflow`, `noOptions`, `loading`, `loadMore`, `unknownOption`, `rangeStart`, `rangeEnd`, `locked` and `formErrors`. They are overridden through `strings` like the others. The typings in `@reflexify/agentflow-elements/jsx` carry the six new tags and the detail types `DateRangeChangeDetail`, `NumberChangeDetail`, `SelectChangeDetail`, `ComboboxChangeDetail` and `ComboboxSearchDetail`, and the kit exports `SelectOption`, `ComboboxOption`, `PickerQuery`, `PickerPage`, `PickerSource`, `FormError` and `AfSubmitDetail`. No existing property, event, part, string key or class was renamed or removed: `af-date` and `af-person-picker` gain the properties above, and every other element is as it was.

Its `src/module/kit.tsx` holds the wrapper for every kit element in the pattern the UI module skill teaches, and `src/module/FormSection.tsx` a form built from `af-form`, `af-fieldset`, `af-field` and each input. The six new tags need no check, because the module's own import defines them. `reference/records-api.md` points the picking of people, units and records at the new inputs, `reference/checklist.md` and the design guide's checklist gain four questions, and `reference/pitfalls.md` gains four entries. The UI kit grows from sixteen elements to twenty-two, and its stylesheet gains the classes that lay out a list, a record's page and a filter bar. `<af-scroll-area>`, `<af-tabs>`, `<af-splitter>`, `<af-pager>`, `<af-copy-button>` and `<af-markdown>` are new; `af-dialog`, `af-menu` and `af-select` each gain something optional. No existing property, event, part or class was renamed or removed, so existing markup keeps working. What changes in it that can be seen: its scrollbars (next paragraph); `.af-chip[aria-disabled="true"]` dims any chip to 60% with a `not-allowed` cursor, a status `<span>` and a link included, and a link chip so marked no longer lights under the pointer; the `.af-tabs` tab rules match a tab anywhere inside the list rather than only a child of it; and `af-dialog`'s body padding is on its scroller's viewport, not on the `body` part, so a page's `af-dialog::part(body) { padding: … }` no longer changes it (style `::part(viewport)` instead). One thing differs in kind: `af-splitter` shows a value before the page sets it back. Every other kit element is controlled and shows a new value only once the page sets it, but a splitter that waited for the page on every pointer move would stutter, so its panes follow the pointer at once and the page hears of the drag when it ends.

`<af-scroll-area>` is the kit's scroller as an element, and every kit scrollbar is now that scroller, but for the tile frame's last-resort scroll in a host card shorter than its figure, which stays the browser's (a drawn one on every tile cost Safari seconds a page). It takes `axis` (`vertical`, the default, `horizontal` or `both`) and `label` (a name for the viewport, which is then a region), holds the page's content in its default slot, and has a read-only `viewport` property: the element inside its shadow root that scrolls, which a virtualised list reads, auto-scroll and a restored scroll position set, and the page listens to for `scroll`, since the element itself raises no events. Its parts are `viewport`, `content`, `scrollbar` (one for each axis), `thumb` and, with `axis="both"`, `corner`. The browser keeps the scrolling (the wheel, touch, the keys, find in page, scroll anchoring, `scrollIntoView` and `position: sticky`, which sticks to the viewport's top and not the page's); the kit hides the native scrollbars and draws AgentFlow's `ScrollArea` over them, a 10 px gutter holding a rounded thumb that shows while the pointer is over the area or it scrolls, fades 150 ms after both end, stays shown under reduced motion and forced colours, and is drawn only for an axis that overflows. The viewport is a tab stop while its content overflows and holds nothing Tab reaches (the browsers' own rule, which Safari does not apply), and not otherwise, so an overflowing `af-dialog` body holding a form is no stop, one holding plain text is a stop named by the dialog's heading, and a board column of card links is none. What scrolled by itself before is now this scroller: the lists of `af-menu`, `af-select`, `af-combobox` and `af-person-picker`, `af-dialog`'s body, the rich editor's mention menu, and `af-tile`'s tables, prose tables, code blocks and text body, so their native scrollbars are replaced by the drawn ones, and each of those elements gains the parts `viewport`, `scrollbar` and `thumb` (`af-tile` also `corner`). The lists of a menu, a select, a combobox, a person picker and the mention menu are not tab stops, since their arrow keys scroll the highlight and Tab closes them, and the tile's scroll regions keep the solid outline they had, and are a tab stop under the same rule, so a list with `drill`, whose rows hold buttons, is no longer one. The kit's own sources hold no plain `overflow: auto` or `overflow: scroll` outside the scroller, which `test/kit/no-plain-scroll.test.ts` checks.

`<af-tabs>` takes `items` (`TabItem[]`, each `{ value, label, disabled?, reason? }`; a property only), `value` (the shown tab), `label` (the tab list's name) and `variant` (`pill`, the default, `line` or `segmented`, the looks of the `af-tabs` classes). Each panel is slotted by its item's value (`<div slot="activity">`), stays in the page's tree and keeps its state, and only the shown tab's panel is not `hidden`. A click, an arrow key (which wraps at the ends and skips a disabled tab), Home or End asks for a tab with `tab-change` `{ value }`; the element does not change tab itself, the page sets `value`. A disabled item shows its `reason` in a tooltip and carries it as its `aria-description`. Its parts are `list`, `tab` and `panel`. `<af-splitter>` holds two panes slotted as `start` and `end` with a handle between them. It takes `size` (the start pane's share in percent, 50 by default), `min` (20), `max` (80), `orientation` (`horizontal`, the default, or `vertical`, which stacks the panes) and `label` (the handle's name, `Resize panes` otherwise). A drag moves the panes at once; `size-change` `{ size }` is raised when the drag ends and after each arrow key, Home or End that moved the handle; and every `size` the page sets moves the panes onto it, even the value they already held, so a page keeps them in step by setting `size` from the event. Its parts are `start`, `end` and `handle`. A pane does not scroll: put an `af-scroll-area` in a pane whose content does. While a drag is live the library puts a `<style>` that sets the page's cursor into `<head>` and removes it when the drag ends, as `react-resizable-panels` does on AgentFlow's own pages. Neither event is named `change`, because a `change` raised by a control inside a panel or a pane bubbles through the element, and a listener for the element's own value would read the control's.

`<af-pager>` draws AgentFlow's pager for a list the page pages itself. In `pages` mode, the default, it shows the rows-per-page select (with `pageSize` and `pageSizes`), the range (`26–50 of 1,240`, from `rangeStart`, `rangeEnd` and `total`) and Previous and Next, from `hasPrev` and `hasNext`; in `more` mode it shows `Showing 50 of 1,240` (from `shown` and `total`) and a Load more button while `hasMore` is set. `busy` locks the buttons, which keep their focus. It raises `prev`, `next`, `more` and `page-size-change` `{ pageSize }`, and never pages itself: the page sets the properties back. `controls` names the list it pages (an id in the same root, of the element whose direct children are the rows: a list, or a table group's `tbody`), so its buttons reference it through ARIA element reflection, which reaches across the pager's shadow root where an id cannot, and carry the `aria-controls` attribute as well; with `focus-new` focus moves to the first row that arrived after Load more, the first child the list did not hold at the press, wherever the page put it (before a Load more row that stays last, say), or to the `status` part when no row arrived, while the `status` part, a `role="status"` region, says how many arrived (`25 more loaded`). Its parts are `prev`, `next`, `range`, `page-size`, `more` and `status`. The SDK gains `cursorList(fetchPage)`, exported from `@reflexify/agentflow-sdk` with the types `CursorList`, `CursorListState` and `CursorPage`, which holds a cursor-paged list's state for a pager: `fetchPage(cursor, signal)` returns `{ items, next_cursor }`, and `state` and each call of `subscribe(listener)` carry `{ items, hasPrev, hasNext, busy, error }`, the stack of cursors behind Previous kept inside. `next()`, `prev()`, `reload()` and `reset()` (the first page again, with the stack forgotten, for a new filter or page size) each return a promise. A new call aborts the one before it and a late answer is dropped, and a server that hands back a cursor already in the stack has no next page.

`<af-copy-button>` is a 24 px ghost icon button that copies `value`. It asks `navigator.clipboard.writeText` first, inside the click, and falls back to a temporary textarea in its shadow root and `execCommand('copy')`; for two seconds the icon is a check, and a visually hidden `status` part says `Copied` or `Couldn't copy`. It takes `value` and `label` (its name, `Copy` otherwise), and its parts are `trigger` and `status`. `af-copy` `{ value, ok }` is raised once per press, after the outcome is known; `ok` is false when the browser refused, and an empty or missing `value` is a failed copy that writes nothing. The event is not `copy` because the browser's own `copy` event shares the name. `<af-markdown>` draws Markdown read-only, as AgentFlow's `MarkdownView` does: GFM (tables, task lists, strikethrough) with a single newline as a line break, raw HTML as its own characters and an image as its alt text. It takes `value`, `mentions` (the response's map; a mention token `@[label](mention:kind/id)` is drawn as the editor's read-only chip, never as an id) and `schemes` (URL schemes kept as links beside http, https, irc, ircs, mailto and xmpp, such as `af-mention:`; `javascript:`, `vbscript:` and `data:` stay text even when listed). A link opens in a new tab after a cancelable `af-link` `{ href }`, which the page stops with `preventDefault()` to route the link itself; a pressed mention chip raises it with `mention:<ref>`. It is the tile's text parser with the same bounds (the first 20,000 characters are read as Markdown, and a body built to make the parser slow is shown as typed). Its part is `content`; a table or a code block in it scrolls in the kit's scroller. Its code is a chunk loaded when the first `af-markdown` connects to the page, as `af-tile`'s is, so `marked` stays out of what every page loads, and until the chunk lands `content` is empty and `aria-busy="true"`; a chunk that cannot load leaves the value shown as plain text with its line breaks, and the next connect tries again.

Three existing elements each gain something optional. `af-dialog` takes `placement="end"` (the default is `center`): the same `<dialog>`, docked at the right edge, as tall as the viewport and `min(75vw, 384px)` wide, as AgentFlow's right Sheet, with the same parts, slots and `close` reasons; it slides in over 500 ms (not under reduced motion) and closes at once, since a native dialog closes as soon as it is told to, and a kit popup slotted into it rises above it. `af-menu`'s `items` takes groups and checkable items beside plain items: an entry with `items` is a group (`MenuGroup`, `{ id, heading?, items }`, drawn with its heading and a separator), and an item takes `type` (`checkbox` or `radio`) and `checked`. `select` then carries `checked`, the state a checkable item would take; picking one closes the menu, as a plain item does, and its check moves only when the page sets `checked` back. The new parts are `group`, `heading`, `separator` and `indicator`. `af-select` takes `size` (`sm`: a 32 px trigger in the same 14 px type, as AgentFlow's `SelectTrigger size="sm"`).

`KitStrings` gains twelve keys, all optional and each with English and Vietnamese text: `resizeHandle`, `previous`, `next`, `rowsPerPage`, `pageRange`, `pageRangeOpen`, `shownOf`, `shownOnly`, `moreLoaded`, `copy`, `copied` and `copyFailed`; the five that carry a range or a count are templates over `{start}`, `{end}`, `{total}`, `{shown}` and `{count}`. The typings in `@reflexify/agentflow-elements/jsx` carry the six new tags, with the listeners `ontab-change`, `onsize-change`, `onprev`, `onnext`, `onmore`, `onpage-size-change`, `onaf-copy` and `onaf-link`, the detail types `TabChangeDetail`, `SizeChangeDetail`, `PageSizeChangeDetail`, `AfCopyDetail` and `AfLinkDetail`, and the element type `AfScrollAreaElement` with its `viewport`; `MenuSelectDetail` gains `checked`, and the kit exports `MenuEntry`, `MenuGroup` and `TabItem`.

New classes for a module's own markup, each drawn to compute the styles of the AgentFlow piece it comes from and compared with it in `e2e/kit-parity.spec.ts`; the kit README gives the markup, and lists the colours that have no token with the difference measured. The state and piece classes: `af-empty` is an empty state in a centred column, and `boxed` makes it a dashed card; `af-error` is a screen's error, with an icon tile, a title, a body, actions and technical details whose trace scrolls in an `af-scroll-area`; `af-repeater` is a repeating group of fields, each row a card whose head holds an `af-drag-handle` and a remove button (moving a row stays the page's); `af-file-chip` is a file's pill with its name and a download link. A Human step can end itself on a condition, with `endWhen`: a condition over `subject.record.<field>`, written with a Decision's operators, checked when the step opens and after every change to the record. `label` is the outcome it records, and `then` takes one of the step's actions or a branch of its own, read downstream as `output.action == "__condition_met"`. An entity can carry starter records, with `seed`: a list of literal record bodies that the install creates once per natural key, at most 1,000 in a package. An upgrade or a reattach seeds only keys it has not seeded, so an admin's edit or deletion stands, and undo removes the starter records nobody touched. Starter records wait while a natural key the same release adds is still being built, and the next upgrade or reattach seeds them, so a key and its starter records are faster in two releases. An AgentFlow deployment from before seeds refuses the whole package. `entities.md` ("Starter records: `seed`", and a section on starter records an app creates itself), `pitfalls.md` and `sandbox-testing.md` ("What a sandbox holds") say so.

A module can read a record's runs and what each run did. The generated API types gain `list_record_runs` (`GET /entities/{entity_id}/records/{record_id}/runs`, a page of run headers newest first, for anyone who can read the record) and `get_run_trace` (`GET /instances/{instance_id}/trace`: each step's label, kind, status, timings and attempts, and for an agent step its skills, a count per tool and the memory it drew on, counted by type). Neither returns error text, token counts, inputs, outputs, prompts or memory titles. Through an installed app only runs of covered workflows are told, and a run about a record is traced only if the app can read the record. The generated types also catch up on entity sources (`EntitySourceView`, `SourceState`, `Entity.source`), which they had fallen behind on. `records-api.md` ("A record's runs, and what a run did") describes both operations.

An entity's `work.module_page` names the page of the package's module its records open at from My Work: a path holding `{{ record_id }}`. It needs the package's `ui` and the entity's `work_surface`.

A module can read what each agent its package installed did over a window. The generated API types gain `get_app_agent_activity` (`GET /app/agents/activity`, for an installed app only) with `AppAgentActivity`, `AgentActivity`, `AgentActivityAgent`, `AgentActivitySteps` and `AgentActivityLearn`: for every agent the package installed, in key order, the steps that succeeded and failed and the Learn counts proposed, created, confirmed and dropped, over a window of at most 92 days (the last 30 days when `from` and `to` are absent). A retried step counts once, by its last attempt, and a step falls in the window of its first call. Only runs the person could see through the app count. Nothing a run took in or produced is told. `records-api.md` ("An app's agents over a window") describes the operation.

The test kit's `idsByKey<K>()` takes the package's `LogicalKey`, and its result is then typed `Record<K, string>`; without `K` it is `Record<string, string>` as before. `getAppObjects<K>` works for module code only: from a sandbox test's `as(handle)` client it is refused with `APP_CALLER_REQUIRED`, so a test uses `idsByKey<LogicalKey>()`. `waitForTask` waits 120 s unless given `{ timeout }`; the sandbox-testing sample passes 60 s, so its `testTimeout` of 180 s holds the task wait, the record poll and 60 s of room.

`upgrading-the-sdk.md` gains the steps for a project made from an older starter to adopt the generated types: run `types`, commit `src/generated/app.ts`, and append `agentflow-app types --check` to `test` when the project has a UI module.

The test kit gains `waitForTask(client, stepKey, recordId)`, which polls the person's live work until the task at a step on a record is there, and `completeTask(client, task, action, { payload })`, which claims it when nobody holds it and submits the action (a payload `_action` never overrides it).

`getAppObjects<K>(client)` and `AppObjects<K>` take the package's logical keys (`LogicalKey` from `agentflow-app types`): `find`, `id` and `satisfies` then refuse another key at compile time, except with `{ source: 'bound' | 'exported' }`. Without `K` they take any string, as before, and an `AppObjects<K>` is assignable to a plain `AppObjects`.

The starter ships `src/generated/app.ts`, and its `test` script ends with `agentflow-app types --check`; `init` keeps both only when the project has the UI module, and writes the project's id into the file.

`build --check` (and so `lint` and `deploy --sandbox`) compares `package/ui` with the module as `build` writes it, byte for byte: the `prebuilt` folder, or a Vite build into a temporary `.agentflow/ui-check-*` folder, as deep as `package/ui` so source maps match. `pnpm check` compares package/ui with the module when package/ui exists, so a module that was changed and not built is `PACKAGE_STALE`; with no `package/ui` (git ignores it) the check reports nothing for the module, and `seal` still refuses a module never built. Without a declared module, a leftover `package/ui` is now extra (`PACKAGE_STALE`): `pnpm build` removes it.

The mirror no longer carries `examples/support-desk` or `examples/projects`: each is its own repository now. The skills no longer point into them.
